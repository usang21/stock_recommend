# 추천 결과 사유 분석 기준

이 문서는 피드백 루프 2단계 — 과거 추천 종목이 왜 올랐고 왜 내렸는지를 분석하는
기준이다 (DESIGN.md §13). 분석 결과는 학습 기록에 누적되어 이후 추천에 반영된다.

## 입력

추천 후 1~5거래일이 지나 **상승(+3% 이상) 또는 하락(-3% 이하)으로 판정된**
종목들이 주어진다. 종목마다 다음이 함께 온다.

- 추천 당시의 순위와 추천 근거
- 그 종목을 낸 전략 목록
- 추천일 종가, 현재가, 등락률, 경과 거래일 수

보합(-3% ~ +3%)으로 판정된 종목은 입력에 포함되지 않는다. 학습할 만한 신호가
뚜렷하지 않기 때문이다.

## 분석 절차

1. 오른 종목들에서 **공통점**을 찾는다. 어떤 전략 조합에서 나왔는지, 추천 근거가
   어떤 유형이었는지(재료 / 수급 / 추세 / 신고가), 몇 개 전략을 동시에
   통과했는지를 본다.
2. 내린 종목들에서도 같은 방식으로 공통점을 찾는다.
3. 두 집단을 **가르는 특징**이 있으면 그것을 기록한다. 없으면 없다고 기록한다.
4. 이번 관찰이 기존 학습 기록의 내용과 **어긋나면** 그 사실을 밝힌다. 기존
   내용을 조용히 덮어쓰지 않는다.

## 작성 기준

- 표본이 적다는 점을 항상 의식한다. 종목 한두 개를 보고 일반 법칙을 만들지 않는다.
  근거가 약한 관찰은 "표본이 적어 단정하기 이르다"고 명시한다.
- **검증 가능한 형태로 쓴다.** "전략1 단독 통과 + 재료가 MOU인 종목 3건이 모두
  하락" 처럼 다음에 대조할 수 있게 쓴다. "시장 분위기가 나빴다" 같은 사후
  설명은 쓰지 않는다.
- 시장 전체가 빠진 날이면 종목 고유의 문제와 시장 영향을 구분한다.
- 이미 학습 기록에 있는 내용과 같은 관찰이면, 반복해 쓰지 말고 **사례가
  누적됐다**는 점을 쓴다.

## 출력 형식

다음 JSON 하나로만 응답한다 (설명 문장 없이 JSON만):

```json
{
  "perStock": [
    { "code": "005930", "analysis": "이 종목이 오른/내린 이유 1~2문장" }
  ],
  "lesson": "이번 회차에서 얻은 관찰. 추천 기준에 어떻게 반영해야 하는지까지 2~5문장으로.",
  "skip": false
}
```

- `perStock`은 입력으로 주어진 종목 전부에 대해 쓴다.
- `lesson`은 학습 기록에 한 항목으로 누적된다. 이번 회차에서 새로 배울 것이
  없으면 `skip`을 `true`로 두고 `lesson`을 빈 문자열로 둔다 — 의미 없는 항목으로
  학습 기록을 채우지 않기 위함이다.
